# 02. MVP要件

## スコープ

MVPの完成条件は **モードA（HTMLプレビュー）** と **モードB（JSON生成）** の両方が最低限動作し、非破壊・基本検証が実装されていること。

### モードA：HTMLプレビュー生成

| ID | 要件 | 優先 |
|---|---|---|
| A-01 | コマンド引数から直接渡された日本語文字列を処理できる | Must |
| A-02 | UTF-8の `.md` を読み込める | Must |
| A-03 | UTF-8の `.html` / `.htm` の人が読む本文を抽出できる | Must |
| A-04 | 元の日本語と書き換え後を切り替える **単一のHTMLファイル**を生成 | Must |
| A-05 | オフラインで動き、外部のJS・CSS・フォント等に依存しない | Must |
| A-06 | 見出し、段落、箇条書き等の意味上の順序を維持する | Must |
| A-07 | HTML入力のスクリプト／CSSを引き継がず、コードブロックは翻訳しない | Must |
| A-08 | 原文と変換後が確認でき、注意箇所も読める | Must |
| A-09 | 画面レイアウトの忠実な複製、HTMLフォームの動作再現 | Won't (MVP) |

**入力例（実装後の想定）**

```text
/yasashii-ja "申請を希望される方は、必要事項をご記入ください。"
/yasashii-ja docs/notice.md
/yasashii-ja public/notice.html
```

- ファイル拡張子が `.md` / `.html` / `.htm` のときAモード。
- 引数が既存ファイルパスに一致しない場合、直接テキストとして扱う。ただし、**ファイルパスらしい文字列が未存在なら確認し、誤ってその文字列自体を変換しない**。
- 引数がない場合は処理対象を一つ質問する。勝手に全リポジトリを読み込まない。
- 出力名：`notice.md` → `notice.easy.html`、`notice.html` → `notice.easy.html`、直接テキスト → `yasashii-preview.html`（作業フォルダ）。
- 既存出力がある場合は無断上書きせず、別名にするか、明示的な上書き指示を求める。
- 元のMarkdown/HTMLの実装を変更しない。HTMLプレビューは**元ページそのものではなく文章を確認するためのビュー**。

### モードB：i18n用JSON生成

| ID | 要件 | 優先 |
|---|---|---|
| B-01 | UTF-8の JSON 言語ファイルを読み込める | Must |
| B-02 | オブジェクト階層、キー名、キー順を維持する | Must |
| B-03 | 文字列だけを書き換え、数値・真偽値・nullは変更しない | Must |
| B-04 | 文字列配列を含め、配列の要素数と順序を維持する | Must |
| B-05 | 補間変数・テンプレートトークンを変えない | Must |
| B-06 | 未対応の構文は元の値を保持し「未変換・要確認」と報告 | Must |
| B-07 | `ja.json` から `ja-easy.json` を別ファイルとして作る | Must |
| B-08 | i18nフレームワークへの自動設定追加・画面改修 | Won't (MVP) |

**入力例（実装後の想定）**

```text
/yasashii-ja ./locales/ja.json
```

- `.json` は原則Bモード。JSONが言語ファイルらしくない場合（巨大な一般データ、構造不明）は確認または安全に中止。
- 値の例：`"ようこそ、{{name}}さん"` → `"{{name}}さん、ようこそ"`（`{{name}}` の綴り・個数が完全一致すること）。
- 予約パターンやICU MessageFormatの複雑な分岐は、最初から無理に書き換えない。**壊さずスキップして警告**する。
- `ja-easy` は本プロジェクトの内部バリエーション名。標準のBCP 47言語タグとして扱わない。HTML文書の言語属性は原則 `lang="ja"`。

## 共通の変換要件

**優先順位：意味の保存 ＞ 情報の欠落防止 ＞ 分かりやすさ ＞ 自然な言い回し。**

- 難しい敬語・受け身・二重否定・長文を見直す。
- 一文一義、短文、明示的な主語、分かる語彙、適切な改行や箇条書きを検討する。
- 必要な専門用語は正式名称を残し、可能な範囲で短い説明を添える。
- 原文にない申請方法・日付・金額・場所・連絡先等を創作しない。
- 日付、時刻、数字、金額、固有名詞、電話、URL、条件、例外、対象者、否定、義務・可能性、期間の情報は保持し、疑義は要確認にする。
- 過度なひらがな化や不自然な語の区切りをしない。言語レベルは機械的な保証値として表示しない。
- 法律・医療・緊急・防災に関係する文書は、とくに人の確認が必要だと示す。

## 結果の形式

- HTMLモード：単一HTMLファイル（原文／やさしい日本語切替、レビュー注意事項セクション）＋実行結果の簡単なテキスト報告。
- JSONモード：新規JSONファイル＋変換した文字列数／スキップ数／要確認数などの報告。警告はClaude Code上に表示。機械処理用の詳細レポートファイルは必要になってから検討。
- エラー時は原文に変更を加えず、部分生成ファイルを完成品として残さない。対象外箇所を黙って消さない。

## 非機能要件

- デフォルトはローカルファイル入力。独自バックエンドなし。不要な通信をしない。
- 追加APIキーを必須にしない（Claude Codeが利用するモデルで文章変換）。モデルの送信規約や扱う文章の機密性には注意する。
- 初期対応は UTF-8。巨大ファイルは規定の上限と明確なメッセージで停止する（目安：入力1MiB、JSONの文字列キー数500。実装時に妥当性を検証）。
- 一般的なMac/Linuxで利用しやすくし、Windows互換は将来テスト。依存が必要なら事前条件と導入方法をREADMEに記載。
- 未対応構文に遭遇したら安全にスキップ／中止し、不完全な成功を装わない。

## 受け入れ条件（ユーザー視点）

1. 日本語の短い文章を入力すると、原文／やさしい日本語の両方が切替表示できるオフラインHTMLが得られる。
2. Markdownから見出しと本文の順序を維持したHTMLプレビューを得られる。コードブロックは書き換えない。
3. HTMLからスクリプト等を除外し、意味上の本文を安全に抽出できる。元のJavaScriptは出力で実行されない。
4. i18n JSONを渡すと、すべてのキー・階層・配列要素数・補間変数を維持した別JSONを得られる。
5. ICU等の未対応文字列は原文のまま残り、未変換と報告される。
6. 原文と同名のファイルを上書きしない。既存の出力も無断上書きしない。
7. 重要情報が変わる疑いは警告され、検査できなかった項目を成功扱いしない。
8. 初めての利用者が README の例と一つのスキル起動で処理を完了できる。
