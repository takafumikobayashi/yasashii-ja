# 07. Claude Codeへの引き継ぎ

## 依頼概要

このリポジトリ `yasashii-ja` に、外国人など日本語に不慣れな人にも伝わりやすい「やさしい日本語」の変換用Agent Skillを実装する。

**MVPで作るものは2つだけ**：

1. 直接渡した文章またはMarkdown/HTMLファイルから、通常日本語とやさしい日本語を切り替えられる**単体HTMLプレビュー**を出力する。
2. 既存のi18n用JSON言語ファイルから、構造や補間変数を維持した**別名のやさしい日本語JSON**を出力する。

最重要の価値は、初心者が難しい指示を書けなくても、成果物と確認すべき事項を得られること。原文の意味・条件などを黙って変更しない。

## 作業を開始する前に

1. `git status`、既存ファイル、README、package.json、`.claude` の状態を確認する。
2. `CLAUDE.md` と `docs/01` から `docs/05`、特に `docs/02-MVP-REQUIREMENTS.md` と `docs/03-DESIGN.md` を読む。
3. 既存のユーザー作成ファイルは尊重し、上書きや削除を避ける。
4. MVP外機能の実装・API追加・自動公開をしない。

## 最初のClaude Codeへの依頼文（そのまま利用可能）

> `CLAUDE.md` と `docs/` 以下の設計書を読んで、`yasashii-ja` のMVPを実装してください。
>
> まずはリポジトリ内の既存構成を確認し、設計の矛盾や未決事項を整理してください。大きな変更が必要な場合は理由を示してください。
>
> 実装順序は M0 → M1 → M2 → M3 → M4 です。最初は **M0（基盤）と M1（直接テキスト→切替HTML）** に集中し、動く最小機能と自動テストを作ってください。その後、M2（Markdown/HTML入力）、M3（JSON生成）、M4（品質確認）に進んでください。
>
> 元ファイルは上書きしないこと。入力HTMLのJavaScriptを実行しないこと。JSONのキーと補間変数を変えないこと。意味の不確実性は警告し、未対応構文は安全にスキップすること。テストを実行した結果と、次に着手する作業を報告してください。

## 最初の開発タスク（具体例）

- `.claude/skills/yasashii-ja/SKILL.md` を最小の形式で追加。
- 直接テキストを文章セグメントに変換する処理とテストを追加。
- LLMから受け取る構造化結果のスキーマ検証を追加。
- フレームワーク不要・外部通信不要のHTML生成と切替UIを追加。
- HTMLのエスケープ・スクリプト注入・出力上書き防止のテストを追加。
- READMEに本当に動く使い方だけを記述。未実装の内容はロードマップに残す。

## スコープ逸脱を防ぐチェック

- `ja-easy.json` をWebアプリの言語切り替え設定に自動追加していないか？ → MVP外。
- Word/PDF/CMS対応を追加していないか？ → MVP外。
- 高度な語彙スコアやAIモデル間比較に時間を使いすぎていないか？ → 後回し。
- 修正前の文章・JSON・HTMLを勝手に変更していないか？ → 禁止。
- 自動検査を通過しただけで「意味の一致を保証」と表示していないか？ → 禁止。
