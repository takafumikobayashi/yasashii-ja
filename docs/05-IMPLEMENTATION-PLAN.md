# 05. 実装計画

## 基本方針

まず最短で **直接テキスト→切替HTML** を成立させ、そのあとに Markdown/HTML入力とJSON生成を積み上げる。幅広い機能を入れるより、データ破壊を防ぐ設計とテストを優先する。

## やらないことを守る

- 既存Webサイトへの自動的なi18nライブラリ導入は別プロジェクト／後続フェーズ。
- JSONのすべてのi18n方言を一度にサポートしない。未対応は非破壊スキップ。
- 専用Webアプリ、SaaS、外部APIサービス、プラグインマーケットプレイスはMVP必須にしない。
- 元のHTMLサイトをそのまま翻訳済みサイトとして複製しない。生成物は**比較プレビュー**。
- スキル自体が勝手に本番環境にファイルを適用しない。

## 初めに決める必要がある技術項目

→ 決定内容は [08-DECISIONS.md](08-DECISIONS.md) に記録。

- Node.jsの最低バージョンとパッケージマネージャー
- skill内部スクリプトと `src/` の責務境界
- パーサー（Markdown/HTML）の採用ライブラリ
- LLMの構造化出力の検証方法
- ICU記法の検出範囲・変数の厳密な比較方法
- 出力先と既存ファイルがある場合の既定挙動

技術選定は実装担当Claude Codeに委ねるが、既存構成を尊重し、理由と代替案を短く記録する。
